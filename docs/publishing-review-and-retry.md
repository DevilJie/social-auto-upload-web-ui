# 发布前人工验收与失败补发

## 行为

- 「发布提交方式」在系统设置中按 渠道 × 发布类型（视频/图文/文章）粒度控制，覆盖所有渠道实际支持的发布链路。开启后填写完成保留浏览器，等待用户亲自提交；关闭则程序自动点击平台发布按钮。设置保存后对下一个发布任务立即生效。
- 人工验收只有在观察到用户提交动作和平台成功信号（成功页 URL 或成功文案）后才记录成功；确认弹窗、字段校验错误会继续等待；关闭页面按取消处理，绝不算成功。程序在验收期间不做任何自动输入，等待没有超时。
- 开关存储在 settings 表 `manualReviewMatrix`（渠道×类型 JSON）；旧的全局 `manualReview` 仅作一次性迁移基线：矩阵缺失且旧值为 true 时，视为 抖音/小红书/快手/B站/视频号/YouTube 的视频链路 + 抖音/小红书/快手的图文链路（共 9 个组合）开启。
- 图文与文章发布为同步 HTTP 提交，人工验收期间前端发布按钮保持等待状态；生产模式的 Waitress 已将连接超时调大到 3600 秒以适配长时间人工确认。
- 标题、正文和整组标签填写后的暂停为 5 秒，不是每个字符暂停 5 秒。它用于给页面更新留出时间，不保证避免平台风控。
- 视频发布历史里的失败账号提供“重新发布”，从数据库快照恢复到编辑页，仅选择该账号，清空旧定时时间。再次提交产生新记录，成功账号不会一并重发。旧记录缺少的配置使用当前默认值，原素材被删除时需重新选择。
- 视频标签输入最多 10 个；提交时快手保留前 4 个、抖音保留前 5 个，其余保留前 10 个。抖音活动/正文话题及小红书正文话题占用相应名额。
- 有“无需声明/标注”选项的平台默认使用该选项，用户仍需按作品内容选择。小红书的“无需声明”表示跳过声明操作。
- YouTube 明确选择“改动内容：否”可以通过校验。上传入口等待实际文件输入框，失败时给出可定位的错误。
- 公众号识别“创建文件失败”“上传失败”“转码失败”，不再在可见错误出现后继续等待 4 小时。这是错误处理修复，不宣称解决微信服务端拒绝创建文件的所有原因。

## 在另一台机器运行

沿用 README 的安装/启动步骤，需要 Python、Node.js、项目依赖及可运行的浏览器环境。依赖通过 `backend/requirements.txt` 和两个 npm lockfile 安装；不复制旧机器的虚拟环境或 `node_modules`。视频处理仍需 README 中的 FFmpeg 环境。

数据目录由 `SAU_DATA_DIR` 或仓库默认 `data/` 决定。不要把 Cookie、数据库、素材、日志或浏览器截图提交到 Git；在新机器上重新登录账号并导入素材。历史里的本地素材路径不提供跨机器自动迁移保证。

人工验收需要可见的浏览器窗口；无图形界面的服务器无法直接完成人工验收。页面选择器依赖平台实际页面，离线测试不能替代账号实测。

## 验证与隐私

CI 在 Windows 和 Linux 安装依赖，运行新增离线回归、前端构建和 MCP 检查。测试使用合成页面、临时数据库和虚构账号，不登录或上传真实作品。Node.js 必须在 PATH 中，公众号测试会执行真实的等待逻辑和页面状态检测 JavaScript。

提交前执行 `python scripts/check_public_diff.py --base origin/master` 并人工检查完整 diff。该脚本只检查本次新增内容中的常见敏感模式；不能证明不存在所有类型的敏感信息，也不扫描或修改上游历史。
