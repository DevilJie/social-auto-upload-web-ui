# 平台发布 · 商品/店铺关联功能实现说明

> **目的**：淘宝光合"关联商品/店铺"是当前唯一落地的实现。本文档沉淀完整方案,**供后续其他平台(抖音/快手/视频号等)对接相同功能时借鉴**,避免重复踩坑。

---

## 1. 功能概述

在视频发布时,允许创作者从平台的"商品库"或"店铺库"中选择若干项,关联到本次视频上(常见场景:带货视频、店铺引流视频)。

核心难点:
- **完整商品/店铺标题太长**(如"小米17 Pro 16GB+512GB 骁龙8 Gen4..."),在发布页搜索框用完整标题搜不到结果
- **完整标题做精确匹配**容易失败(空格/特殊字符/截断)
- **每次搜索结果不一样**(平台商品库会按推荐规则动态排序,翻页/筛选项都影响)
- **同一发布流程可能选多个商品**,但每个商品的"找到路径"不同

## 2. 设计核心:trace 快照 + 分组重现 + itemId 精准定位

### 2.1 三大设计决策

| 维度 | 决策 | 理由 |
|---|---|---|
| 轨迹数据模型 | **每商品一份状态快照**(选中那一刻面板状态) | 一刀切的"当前状态"会让后选商品继承前选的搜索词 |
| 范围 | **商品 + 店铺一起改造** | 同一套 picker 弹窗,逻辑对称,代码复用 |
| 失败处理 | **任一商品找不到即中断整个视频发布** | 凭"运气"匹配的商品可能错位,用户必须知道 |

### 2.2 三件套:`trace` + `id` + `面板只开一次`

1. **trace = 选中时的面板状态快照**
   - `{tab, keyword, rule, category}` 4 个字段
   - 用户点卡片的那一瞬间快照,后续面板状态变化不影响已选商品的 trace

2. **itemId 作为精准定位锚**
   - 商品:淘宝 itemId(从 `a[href*="item.taobao.com/item.htm"]?id=xxx` 提取)
   - 店铺:id = title || url(回退)
   - 发布时按 itemId 在结果列表里精确匹配,不再依赖完整 title

3. **面板只开一次**
   - 不要"每组重开重关",关闭面板后立即重开按钮还没重新渲染好,`wait_for` 8s 超时
   - 所有组在同一个面板里切换搜索词/筛选/勾选,光合会自动保留已选商品(最多 6 个)
   - 最后统一点"确定"提交

## 4. 数据结构

### 4.1 前端 form 字段

```js
// 持久化在 drafts.draft_data JSON,无需新字段
form.guangheProducts = [
  {
    title: "小米17 Pro 16GB+512GB 骁龙8 Gen4...",  // 显示用
    image: "https://gw.alicdn.com/...",            // 显示用
    id: "674528301234",                          // 商品 itemId / 店铺 title||url
    trace: {                                     // 选中那一刻面板快照
      tab: "preferred",                           // 'bought' | 'preferred' | 'shop'
      keyword: "小米17",                          // 搜索框文本
      rule: "主推品",                             // 推荐规则(默认"全部")
      category: "全部"                           // 品类(默认"全部")
    }
  },
  ...
]
```

### 4.2 trace 签名(用于分组)

```python
def trace_signature(trace: dict) -> tuple:
    return (
        trace.get("tab", ""),
        trace.get("keyword", ""),
        trace.get("rule", ""),
        trace.get("category", ""),
    )

# 签名相同的商品归为一组,共享一次面板状态复原
groups = {}
for item in items:
    sig = trace_signature(item["trace"])
    groups.setdefault(sig, []).append(item["id"])
```

### 4.3 提交 payload(POST /api/publish)

```python
# 新格式(主)
guangheLinkType: 'product' | 'shop'
guangheProducts: [{title, image, id, trace}, ...]  # 商品
guangheShops:    [{title, image, id, trace}, ...]  # 店铺

# 旧格式兼容(降级):裸字符串数组
guangheProductNames: ["name1", "name2", ...]  # → 走 _legacy_link_by_title
```

## 5. 关键流程

### 5.1 用户选品流程

```
打开 picker 弹窗
  ↓
后端 picker 创建常驻 headless browser(发布页同会话池)
  ↓
前端 POST /api/taobao_guanghe/picker/open
  ↓ 后端:直接 goto 发布页 URL + cookie 检查 + 切 radio + 点"添加商品"
  → 返回: {items, filters, has_more}
  ↓
用户操作:
  - 搜"小米17" → searchKeyword.value = "小米17"
  - 切"主推品"  → activeRule.value = "主推品"
  - 切"全部"    → activeCategory.value = "全部"
  - 加载更多    → 不记录在 trace 里
  - 点商品卡片 → 立即打包当前面板状态:
      trace = {tab, keyword, rule, category}  ← 快照!
      selectedItems.push({title, image, id, trace})
  ↓
点确认 → emit('confirm', [...{title, image, id, trace}])
  ↓
父组件 PublishCenter 写入 form.guangheProducts
  ↓
saveDraft → 序列化进 draft_data JSON
  或直接 → 提交 /api/publish payload
```

### 5.2 发布复原流程

```
POST /api/publish(payload)
  ↓
app.py 4 处路由透传 payload → kwargs
  ↓ kwargs['guangheProducts'] = [{title, image, id, trace}, ...]
platform.publish_video(**kwargs)
  ↓
publish_video 读取 guangheProducts/guangheShops → link_items
  ↓
_upload_single_video → _link_products_or_shops(frame, link_type, link_items)
  ↓
_link_products_or_shops → _replay_groups(frame, link_type, link_items, max_load_more=5)
  ↓
_replay_groups:
  1. switch_radio + click_add_card + wait_panel_ready   ← 面板只开一次
  2. groups = _group_by_trace(items)                      ← 按 trace 签名分组
  3. for gi, (trace, group_items) in enumerate(groups):
     - switch_tab(frame, trace.tab)                      ← 无条件复原
     - click_filter(frame, "推荐规则", trace.rule)      ← 商品模式无条件复原
     - click_filter(frame, "品类筛选", trace.category)  ← 商品模式无条件复原
     - search(frame, trace.keyword or "")               ← 无条件复原(空串清空搜索框)
     - pending = set(target_ids)
     - for attempt in range(6):  # 首次 + 5 次加载更多
         res = locate_and_check(frame, type_, pending)
         if res["disabled"]: raise RuntimeError
         for tid in res["checked"] + res["already"]:
             pending.discard(tid)
         if not pending: break
         if attempt < 5: clicked = load_more(frame); if not clicked: break
     if pending: raise RuntimeError(未找到的 id)
  4. 点"确定"关闭面板                                     ← 关闭只一次
```

### 5.3 边界处理

| 场景 | 检测 | 处理 |
|---|---|---|
| 旧数据无 `id`/`trace` | `not it.get("trace")` | 退回 `_legacy_link_by_title`(title 搜索+span[title] 匹配) |
| 字符串数组(极旧数据) | `isinstance(it, str)` | 包成 `{title: it}`,走 legacy |
| 5 次加载更多后仍未找到 | 计数器 + 剩余集合比对 | `raise RuntimeError("未找到的 id...")` |
| 商品 disabled | 抓取阶段 `disabled: True` | `raise RuntimeError("商品不可选(disabled): ...")` |
| 搜索后列表空 | `_scrape` 返回 `[]` | 立即中断(不空等加载更多) |
| 切 tab/筛选无响应 | 切完后校验 active | 重试 1 次,仍失败中断 |
| 浏览器/网络异常 | 异常冒泡 | 现有 except 捕获 + 截屏 + 记日志 |

## 6. 核心 DOM 操作(`_link_ops.py`)

> **关键**:这套函数必须接受 `frame` 作为第一个参数,**同时供 picker.py(选品浏览器)和 platform.py(发布浏览器)使用**,保证两条路径 DOM 操作一致。

| 函数 | 作用 | 备注 |
|---|---|---|
| `trace_signature(trace)` | 计算 trace 签名,用于分组 | 纯函数 |
| `switch_radio(frame, type_)` | 切商品/店铺 radio | `.next-radio-label` + 文本 |
| `click_add_card(frame, type_)` | 点"添加商品/店铺"卡片 | `get_by_text("添加商品", exact=True)` |
| `wait_panel_ready(frame, type_)` | 等面板就绪 | 商品:等 tabs;店铺:等搜索框 |
| `switch_tab(frame, tab)` | 切 bought/preferred | 切完校验 active |
| `click_filter(frame, row, opt)` | 点筛选选项 | 在激活 tabpanel 内 |
| `search(frame, keyword)` | 输入搜索词并回车 | 空 keyword = 清空搜索框 |
| `load_more(frame)` | 点"加载更多" | 无按钮时滚到 tabpanel 底部触发懒加载 |
| `scrape(frame, type_)` | 抓取当前列表 | 商品:itemId 提取;店铺:title 提取 |
| `_click_item_by_id(frame, type, id)` | 按 id 找并勾选 | 返回 clicked/already/disabled/not_found |
| `locate_and_check(frame, type, target_ids)` | 定位+勾选+返回分类 | 4-bucket dict |

**关键锚点**:
- 商品卡片: `a[href*="item.taobao.com/item.htm"]?id=xxx` + 向上找 `label.next-checkbox-wrapper`
- 店铺卡片: `label.next-radio-wrapper` + 找含 img 的最近祖先
- 激活面板: `[role="tabpanel"][aria-hidden="false"]` (限范围内找避免隐藏 tab 干扰)
- 主 frame vs iframe: 光合发布页是跨域 iframe,所有 DOM 操作都要在 iframe frame 内

## 7. 新平台对接 checklist

> 假设要把"关联商品/店铺"功能搬到 **抖音/快手/视频号/X 平台**,需要做以下事:

### 7.1 前端 (`config/platforms.js` + 新组件)

- [ ] 在 `PLATFORMS` 添加平台配置(name / key / logo / color / cssClass)
- [ ] 复用 `GuangheItemPicker.vue`(复制为 `XxxItemPicker.vue`)**或**参数化 picker 接受 type 配置
- [ ] 提取 trace schema。如果平台支持 tab/筛选/搜索,trace 字段一致;否则精简
- [ ] 适配新平台的 DOM 锚点(重写 `scrape` / `_click_item_by_id` / `click_filter` 等)

### 7.2 后端 (`impl/_xxx_link_ops.py`)

- [ ] **抽 helper 模块** `impl/_xxx_link_ops.py`(纯函数,frame-first 参数)
- [ ] 复用 picker session 池机制(同账号同时只能开一个 picker,需要换号时强制 close)
- [ ] 把 DOM 操作代码**从 picker 内部抽出**到 helper 模块,确保选品/发布两条路径共享
- [ ] **trace 模型不变**:`{tab, keyword, rule, category}`(字段语义对新平台做适配,如"rule"可能是"筛选维度1")

### 7.3 后端 (`impl/platform.py:_link_products_or_shops`)

- [ ] 抽 `_replay_groups()` / `_group_by_trace()` / `_legacy_link_by_title()` 模块级纯函数(便于单测)

- [ ] **面板只开一次,所有组在同面板内完成**,最后统一点确定提交
- [ ] **无条件复原 trace 字段**(避免上一组状态污染)
- [ ] disabled / 5 次加载更多未命中 → raise RuntimeError 中断发布
- [ ] 业务层 `_upload_single_video` 调用 `_link_products_or_shops(frame, type, items)`

## 8. 手动验收清单

> 每次对接新平台,跑这套冒烟测试:

1. **轨迹快照保真度**:搜 X → 选 A → 选 B(同状态)→ 清空搜索 → 选 C。Network payload 中 `trace.keyword` 应该是 A、B="X",C=""
2. **分组重现**:发布后端日志应有 `[关联X] 共 N 个, M 组轨迹`,每组独立复原
3. **中断策略**:故意改坏 `trace.keyword` → 验证 raise RuntimeError,含具体 id
4. **草稿持久化**:保存草稿 → 刷新 → 加载 → trace 完整
5. **店铺模式(若有)**:重复 1-4 验证
6. **旧数据兼容**:加载旧草稿(无 trace)→ 验证走 `_legacy_link_by_title`
7. **面板只开一次**:选 3+ 个商品(分不同 trace) → 验证面板不会重复关闭打开

## 9. 已知坑(踩过的)

| 坑 | 现象 | 解决 |
|---|---|---|
| **多进程绑同端口** | Windows 上 `lsof` 杀不干净,新代码不进 | 用 `taskkill //PID //F` 杀干净后重启 |
| **`:global()` 嵌套写法被丢弃** | Vue scoped 不支持嵌套,编译后 CSS 没暗色规则 | 改成扁平 `html.dark .xxx {}` |
| **"添加商品"按钮 8s 超时** | 第 1 组关面板后立即重开,按钮还没渲染 | 面板只开一次,各组在同面板里操作 |
| **`await count()` 不能 await** | Playwright Python 中 `count()` 同步返回 int | 某些版本是 async,需看实际报"object can't be awaited"判断 |
| **`_link_ops` 双 sys.path 双模块** | `from taobao_guanghe import _link_ops` 和 `from impl.taobao_guanghe import _link_ops` 是两个不同模块对象 | 测试时用 `platform_mod._link_ops` 拿同一份引用 |
| **DraftBox 缓存旧 chunk hash** | vite 重启后浏览器报 `Failed to fetch dynamically imported module` | Ctrl+Shift+R 硬刷新 |
